# Observation clock contract (v1)

`timestamp_us` is a nonnegative integer in microseconds. The unit does not establish the clock origin or make independent producer times comparable. `attributes.clock` retains the clock domain and `attributes.clock_alignment` declares how the timestamp reached that domain. New epoch producers emit `clock: "unix_epoch"`, `clock_alignment: "direct_epoch"` and a concrete `clock_source`. Mapped profilers retain their existing named mapping methods; `src/model/clocks.rs` owns their interpretation for both acceptance and queries.

For example, the Rust SDK reads SystemTime for the timestamp and Instant for duration. Its writer emits `unix_epoch/direct_epoch` with `clock_source: "SystemTime epoch with Instant duration"`. Acceptance checks shape, safe time integers and consistency between a recognized epoch mapping and the epoch domain. It does not independently prove the producer's clock accuracy. Timeline can then place this timestamp in a shared epoch view; sampled weights still do not become exact durations.

A V8 profile without its epoch anchor instead emits `runtime_monotonic/unmapped`. Its original timestamp remains useful within that domain, but an epoch query must not position it beside independent epoch producers. `alignment: "all"` returns it in `unaligned_records`; resource queries preserve its domain and do not apply epoch windows to its points.

Missing metadata, an unknown mapping name, a null/opaque domain, and malformed historical metadata remain unknown/unmapped, with the original JSON preserved. They are included in unaligned counts and domains, never defaulted to Unix epoch. New malformed alignment field types fail schema validation; recognized epoch mappings with contradictory or missing domains fail semantic acceptance atomically. Unknown mapping labels remain readable for forward extensions and are not evidence of alignment.

Existing v1 SDK records whose clock field names an actual known epoch source (for example `time.time_ns/perf_counter_ns`) remain aligned with explicit `legacy_epoch_source` provenance in the resource view. This narrow compatibility rule does not upgrade absent metadata or generic `unix_epoch` without a mapping. No historical recording, input identity or retained JSON is rewritten. New SDK records use the explicit domain/mapping/source fields. Alignment describes the declared mapping, not synchronization precision, timestamp uncertainty, causal ownership or universal cross-host comparability.
